# Review and pre-submission checklists

## Review passes (run each, record what it caught)
1. **Claims pass.** Each number, count, version and date has a run, dataset, test or source; rerun on the
   final version.
2. **Reference pass.** Each entry opened at its source; `verify` notes cleared; authors, year, venue match.
3. **Fairness pass.** Related work states others' strengths; our costs and non-goals are in the text.
4. **Honesty pass.** Limitations present; nothing the released version lacks; wording no stronger than data.
5. **Cold-reader pass.** A separate reader (agent or person) given only the PDF: can they state the
   problem, contribution and evidence in three sentences? Give it the paper, not your conclusions.
6. **Mechanical pass.** Clean build, no placeholders (`grep -n "\[\|TODO\|verify\|Replace"`), figures
   regenerate, links resolve.
7. **Integrity pass.** Ethics, consent, COI, funding, contributions, data and code availability, AI use.

Note: a project's own record of paper review is often thin (no log entries, one-line commit messages). Keep a short review log in the paper folder from the start so lessons are not lost.

## Reporting guidelines by field (examples; use the one the venue names)
Randomised trials CONSORT; systematic reviews PRISMA; observational studies STROBE; diagnostic accuracy
STARD; animal studies ARRIVE; qualitative research COREQ or SRQR; simulation studies STRESS (discrete-event
and general), ODD protocol (agent-based models), DOE and model-reporting conventions for system dynamics;
machine learning model cards and reproducibility checklists; surveys CHERRIES; economic evaluations CHEERS.
Where none fits, report: data, methods, parameters, seeds or randomisation, uncertainty, and failures.

## Statistics and data
Name each test and why; report intervals and effect sizes, not only p-values; correct for multiple
comparisons; say what was pre-specified; keep exclusions and missing data explicit; deposit data and code
or state the access conditions.

## Pre-submission checklist
- [ ] Document type and venue guidelines read live, checklist made and dated
- [ ] Length, template, anonymity (if double-blind) met
- [ ] Version, benchmark or data date and hardware stated; reruns done if the thing changed
- [ ] Every number traced; tests or checks green on the final version
- [ ] Figures and tables regenerated by script
- [ ] No `verify`, no placeholders, no TODO
- [ ] Availability: licence, repository, install line, commands, DOI of the exact release or dataset
- [ ] Ethics approval and consent, COI, funding, author contributions, data statement
- [ ] AI disclosure from evidence, recounted today
- [ ] Author details (affiliation, ORCID, correspondence), acknowledgements
- [ ] Limitations and threats to validity written
- [ ] No client, employer or confidential material without permission and approval
- [ ] Cover letter or executive summary written
- [ ] JOSS only: eligibility, research-impact evidence, preview PDF checked
- [ ] The author has said "submit" in this session
